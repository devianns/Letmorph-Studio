# 사용자 흐름과 제작 절차

## 현재 구현된 작업 흐름

1. PNG/JPG/WebP 이미지를 가져오면 원본 자체가 선택된 `기본 이미지` 아이템으로 아이템 목록에 생성됩니다. 기본 움직임이 적용되어 바로 효과를 조절할 수 있습니다.
2. 도구 모음에서 `펜 그리기`를 고르고 캔버스에 점을 찍어 윤곽을 만듭니다. 시작점을 다시 누르거나 Enter를 누르면 영역이 닫혀 새 아이템이 됩니다. `전체 선택`은 기존 아이템에 전체 이미지 복사본을 하나 더 추가합니다.
3. 아이템 목록에서 기본 이미지나 추가 아이템을 골라 이름, 표시 여부, 움직임 종류, 강도, 속도를 수정하거나 삭제합니다. `펜으로 영역 다시 그리기`로 부분 아이템의 범위를 바꿀 수 있습니다. 기본 이미지 아이템을 삭제해도 원본 파일은 유지되며, 도구로 다시 추가할 수 있습니다.
4. 실행 취소(Ctrl+Z) 또는 아이템 삭제로 수정하고 미리보기한 뒤, MP4/WebM 중 형식과 사이클 반복 횟수를 선택해 예상 파일 크기 512MB 이하의 영상으로 저장합니다. 반복 횟수에는 별도 상한이 없으며, 예상 또는 실제 파일 크기가 512MB를 넘으면 안내 후 내보내기를 중단합니다. 1회 사이클은 2.4초이며, 내보내기는 원본이 작으면 원본 해상도를 유지하고 최대 1920px, 60fps, 높은 녹화 비트레이트를 사용합니다. 현재 Chromium이 지원하지 않는 형식은 선택할 수 없으며, 선택한 형식으로 저장할 수 없으면 다른 형식으로 바꾸도록 오류를 표시합니다. `처음으로`는 이미지를 포함한 현재 작업을 닫고 가져오기 화면으로 돌아갑니다.

미리보기 도구 모음의 가이드 토글은 선택 윤곽, 펜 가이드, 캔버스 정보, 줌 안내를 숨겨 움직임만 확인하게 합니다. 아이템 속성에는 9개 프리셋과 강도/속도, 좌우·상하 이동, 회전, 크기의 세부 조절이 있습니다. 세부 축 값은 -100%에서 100%까지 조절할 수 있습니다.

부분 선택 아이템은 모서리 다듬기와 경계 페더를 조절해 날카로운 꼭짓점과 잘린 경계를 완화할 수 있습니다. 페더는 원래 펜 선택 경계 안쪽에만 적용됩니다. 각 아이템에는 잔상을 개별 적용할 수 있으며, 잔상 개수(1~32), 시간 간격(10~200ms), 불투명도와 감쇠 정도를 조절합니다. 잔상은 같은 결정적 움직임 평가기의 과거 시각을 추가 렌더링해 만들며 실제 아이템/이미지 레이어를 복제하지 않습니다.

부분 선택 아이템을 고른 뒤 `경계점 조절`을 켜면 윤곽의 점을 드래그해 위치를 수정할 수 있습니다. 드래그한 점은 원본 이미지 기준 좌표로 저장되므로 확대나 화면 이동에 영향을 받지 않으며, 수정 한 번은 Ctrl+Z로 되돌릴 수 있습니다. 더 큰 범위 변경은 `펜으로 영역 다시 그리기`를 사용합니다.

캔버스는 원본 이미지 둘레에 사방 25%의 움직임 여유 영역을 둔 작업판으로 이미지 비율을 유지해 처음 배치합니다. 휠 또는 `+/-` 버튼으로 최대 16배까지 확대·축소하고 가운데 마우스 버튼을 누른 채 끌어 화면을 이동할 수 있습니다. 펜 좌표는 화면 좌표가 아닌 원본 이미지 안의 비율로 저장하므로 확대율과 이동 위치를 바꿔도 선택 영역과 움직이는 아이템의 위치는 일치합니다. 펜 점 표시는 원본 이미지의 종횡비와 무관하게 원형으로 표시됩니다.

기본 이미지 아이템은 입력 이미지를 직접 나타내고, 펜/전체 선택 아이템은 그 위에 마스크 복사본으로 합성합니다. 추가 아이템은 원본 픽셀을 자르거나 지우지 않으므로 선택한 부분이 움직여도 바닥 그림은 그대로 보입니다. `작업 내보내기`는 편집 아이템과 설정, 원본 이미지를 `.letmorph` 단일 파일에 담고, `작업 가져오기`는 이를 복원합니다. 영상 내보내기와는 별개의 작업 파일입니다. 펜 영역은 처음 생성한 뒤 다시 그리거나 경계점을 조절할 수 있습니다.

이 문서는 Letmorph Studio에서 사용자가 정적 그림을 넣고, 자신만의 움직이는 캐릭터를 만들고, 결과물을 저장하기까지의 경험을 정의한다. 먼저 사용자가 이해하기 쉬운 흐름을 고정하고, 각 단계의 기능과 기술 구현 순서를 그 흐름에 맞춘다.

## 제품 경험의 기준

- 사용자의 목표는 파츠 편집이나 애니메이션 공부가 아니라, 자신이 고른 그림으로 마음에 드는 움직이는 캐릭터를 만드는 것이다.
- 첫 결과까지의 경로는 짧고 안내가 분명해야 한다. 코드 기반 선택 도구와 움직임 프리셋을 제공하고, 사용자는 눈으로 확인해 고친다.
- 각 단계의 화면에는 다음 행동 하나가 분명해야 한다. 전문 용어와 고급 옵션은 기본 경로에서 감춘다.
- 원본 그림은 보존한다. 선택 도구의 결과는 미리보기와 되돌리기를 제공하고, 잘못 선택된 부분을 사용자가 쉽게 수정할 수 있게 한다.
- 결과를 만들기 전에도 저장할 수 있어야 하며, 중단 후 다시 열었을 때 이어서 작업할 수 있어야 한다.
- 결과물의 품질과 기능을 과장하지 않는다. 특정 그림에서 자동으로 복원할 수 없는 부분이나 움직임의 한계를 이해하기 쉽게 알린다.

## Input → 프로그램 → Output

```text
정적 그림
  → 그림 확인 및 프로젝트 생성
  → 캐릭터가 보이는 부분을 프로그램이 준비
  → 사용자가 결과를 확인하고 간단히 수정
  → 준비된 움직임을 선택하거나 조정
  → 재생 미리보기 및 다듬기
  → 움직이는 캐릭터 파일 저장 + 편집 가능한 프로젝트 보관
```

### Input

- 사용자가 가진 캐릭터 그림 파일 (초기 지원 후보: PNG, JPG, WebP)
- 선택 입력: 캐릭터 이름, 원하는 분위기/움직임, 배경 선택
- 원본은 불변 입력으로 프로젝트에 복사하거나 프로젝트가 안전하게 참조한다. 원본 덮어쓰기는 하지 않는다.

### 프로그램이 하는 일

- 파일을 확인하고 그림 크기와 미리보기를 표시한다.
- 그림을 움직일 수 있도록 캐릭터의 주요 부분과 앞뒤 관계를 준비한다.
- 적당한 기본 움직임을 제안하고 캐릭터에 적용한다.
- 사용자가 고른 설정에 맞춰 재생 가능한 장면을 만들고 프레임으로 렌더링한다.
- 편집 상태와 내보낸 결과를 사용자가 지정한 위치에 저장한다.

### Output

- 다시 열어 수정할 수 있는 편집 프로젝트
- 움직이는 이미지 (GIF 우선 검토)
- 추후 선택 출력: WebM/MP4, 투명 배경 프레임 묶음, 정지 PNG, 스프라이트 시트

## 기본 사용 흐름

| 단계 | 사용자가 하는 일 | 프로그램이 하는 일 | 확인/수정 및 다음 단계 |
|---|---|---|---|
| 1. 시작 | 새 캐릭터 만들기를 선택한다. | 짧은 안내와 그림 추가 영역을 보여준다. | 지원 파일과 원본 보존 안내를 확인한다. |
| 2. 그림 추가 | 파일을 끌어놓거나 파일 선택 버튼을 누른다. | 형식/크기를 확인하고 미리보기와 프로젝트를 만든다. | 잘못된 파일은 원인과 해결 방법을 쉬운 말로 알린다. |
| 3. 캐릭터 준비 | 배경 선택 또는 직접 영역 그리기를 한다. | 투명도, 색상, 연결 영역을 이용한 코드 기반 선택 도구로 마스크를 만든다. | 복잡한 경계는 올가미나 브러시로 직접 지정한다. 프로그램이 머리나 팔 같은 의미를 추측하지 않는다. |
| 4. 결과 확인 | 미리보기에서 선택한 영역을 살핀다. | 선택한 영역을 색으로 덮어 보여주고 앞뒤 순서와 간단한 이름을 설정하게 한다. | 부분 지우기/복원, 이름 변경, 순서 조정. 건너뛰기나 되돌리기를 허용한다. |
| 5. 움직임 선택 | 미리보기 예시를 보고 원하는 느낌을 고른다. | 선택한 움직임을 적용하고 강도/속도 기본값을 설정한다. | 예: 살랑살랑, 통통, 좌우로 흔들기. 용어 대신 시각 예시와 짧은 설명을 쓴다. |
| 6. 미리보기 | 재생/일시정지하고 마음에 드는지 본다. | 실제 저장 결과와 같은 엔진으로 반복 재생한다. | 강도/속도, 배경, 반복 여부를 간단히 조절하고 원할 때 이전 단계로 돌아간다. |
| 7. 저장 | 저장 형식과 위치를 정한다. | 선택한 크기/반복/배경으로 파일을 만들고 진행 상황을 표시한다. | 결과 열기, 위치 보기, 편집 계속하기를 제공한다. 프로젝트도 함께 저장하도록 안내한다. |

### 사용자가 겪는 주요 분기

- **파일 형식이 맞지 않음:** 지원 예시를 안내하고 다시 선택하게 한다. 선택 전 상태와 입력 파일은 보존한다.
- **그림에서 캐릭터를 찾기 어려움:** 배경색 선택이 실패하면 올가미나 브러시로 직접 영역을 지정하도록 안내한다.
- **선택 결과가 틀림:** 확대 가능한 미리보기에서 지우기/복원/순서 변경으로 고칠 수 있다. 언제든 되돌리기와 원본으로 돌아가기를 제공한다.
- **가려진 부분을 복원하기 어려움:** 움직임을 줄여 자연스럽게 보이게 하거나, 사용자가 복제/그리기 도구로 직접 보완할 수 있게 설명한다. 보이지 않던 그림을 자동으로 만든 것처럼 가장하지 않는다.
- **내보내기 실패/취소:** 원인과 재시도 방법을 표시하며 편집 프로젝트와 이전 결과 파일을 유지한다.

## 정보 구조와 화면

### 기본 제작 화면

- **중앙:** 캐릭터/애니메이션 미리보기 (가장 큰 작업 영역)
- **왼쪽 또는 하단:** 현재 단계에 맞는 안내와 핵심 조작
- **상단:** 단계 표시, 저장 상태, 실행 취소/다시 실행
- **하단:** 이전/다음 또는 저장/내보내기 같은 현재 단계의 주 행동
- **고급 설정:** 기본 흐름을 방해하지 않는 접기 영역. 필요할 때만 노출

단계명은 결과 중심의 일상적인 표현으로 쓴다: `그림 가져오기 → 캐릭터 준비 → 움직임 고르기 → 미리보기 → 짤 저장하기`. 내부 구현 용어인 `리깅`, `메시`, `키프레임`, `렌더 패스`를 기본 화면의 단계명이나 필수 안내로 쓰지 않는다.

### 단계 화면별 최소 요구

1. **그림 가져오기:** 드래그 앤 드롭, 파일 선택, 지원 형식, 간단한 좋은 결과 팁.
2. **캐릭터 준비:** 진행 상태와 취소, 결과를 기다리는 동안 무엇을 하는지 설명.
3. **확인/수정:** 큰 미리보기, 눈에 보이는 수정 도구, 되돌리기, 건너뛰기.
4. **움직임 고르기:** 썸네일/짧은 반복 예시, 움직임 이름, 강도/속도 같은 쉬운 조절.
5. **미리보기/저장:** 실제 결과와 같은 반복 미리보기, 형식/크기/배경/반복 선택, 저장 위치 선택.

## 성공 기준과 제품 지표

- 처음 실행한 사용자가 도움말 없이 첫 이미지를 불러올 수 있다.
- 기본 경로로 첫 움직이는 결과를 만들 수 있고, 언제든 프로젝트를 다시 열 수 있다.
- 코드 기반 선택 도구가 맞지 않아도 사용자가 원본을 잃지 않고 직접 수정하거나 취소할 수 있다.
- 내보낸 파일을 지정한 앱에서 열 수 있고, 재생이 끝없이 반복되거나 선택한 배경/크기와 다르게 나오지 않는다.
- 관찰 대상: 이미지 추가 완료율, 첫 미리보기까지 걸린 시간, 각 단계 이탈률, 선택 보정 빈도, 내보내기 성공률, 되돌리기 사용 후 복구율.

초기 목표 수치가 없는 상태에서 임의 기준을 정하지 않는다. 사용성 확인 후 현실적인 기준을 정하고 이 문서에 기록한다.

## 이 흐름을 구현하는 절차

사용자 흐름을 먼저 검토하고, 아래 순서로 기능을 만든다. 각 단계가 화면에서 끝까지 동작해야 다음 단계로 넘어간다.

1. **앱 경로 확정:** 시작/새 프로젝트, 그림 가져오기, 프로젝트 저장과 재열기 흐름을 만든다.
2. **입력 수직 경로:** 지원 이미지 읽기 → 미리보기 → 원본 보존 → 재열기를 연결한다.
3. **첫 캐릭터 준비:** 배경 선택, 올가미, 브러시 등 코드 기반 선택 도구와 취소·오류·되돌리기를 구현한다.
4. **사용자 수정:** 선택 결과를 확인하고 직접 고칠 수 있는 시각 도구와 실행 취소를 만든다.
5. **움직임 한 가지 완성:** 하나의 준비된 움직임을 선택해 미리보기와 재생이 되게 한다. 여러 동작보다 첫 동작의 완성도를 먼저 확인한다.
6. **실제 저장 경로:** 같은 재생 계산을 이용해 GIF 등 첫 출력 형식으로 렌더링하고 저장한다.
7. **전체 흐름 다듬기:** 첫 사용자 관점에서 막힘/오해/기다림을 점검하고 문구, 기본값, 오류 복구를 수정한다.
8. **확장:** 추가 움직임, 편집 도구, 출력 형식, 성능과 프로젝트 호환성을 단계적으로 확장한다.

각 구현은 이 문서의 단계 중 어느 사용자 행동을 완성하는지 설명해야 한다. 엔진 내부 기능만 추가하고 사용자가 도달할 수 없는 상태로 남으면, 해당 단계가 완료된 것으로 표시하지 않는다.

## 현재 구현 상태

- 앱 셸과 단계 표시, PNG/JPG/WebP 이미지 선택/드롭이 있다.
- TypeScript application/core 모듈이 형식, 빈 파일, 50MB 제한을 확인하고 이미지 디코딩을 요청해 크기와 프로젝트 메타데이터를 만든다. 브라우저 adapter가 디코딩과 임시 미리보기 URL을 맡는다.
- React UI는 파일 선택, 진행/오류 메시지, 미리보기 표시를 맡는다. 이미지 검사와 프로젝트 생성은 React 컴포넌트에 들어 있지 않다.
- 코드 경계는 `ui`(React 표시/입력) → `application`(사용 사례) → `core/domain`(검증 규칙/데이터)이며, 브라우저 API는 `platform` adapter 뒤에 둔다. 모션 계산은 `engine` TypeScript 모듈에 둔다.
- 사용자는 원본 그림 위에 전체 이미지 또는 펜으로 닫아 선택한 복수 아이템을 올리고, 각 아이템에 세 가지 기본 움직임을 설정해 미리 볼 수 있다. 아이템은 목록에서 다시 선택·이름 변경·숨김·삭제할 수 있고, 부분 영역은 다시 그릴 수 있다. Electron 저장 대화상자를 통해 짧은 WebM 영상을 저장한다. 움직임 계산과 캔버스 그리기는 React 밖의 TypeScript 모듈에서 수행한다.
- 현재 움직임은 이미지 전체를 한 덩어리로 움직인다. 파츠별 분리/수정, 가려진 부분 보완, GIF 출력은 아직 구현되지 않았다.
- 현재 단계 표시 UI는 목표 흐름의 초안이다. 각 단계의 실제 연결과 전환은 미구현이다.
